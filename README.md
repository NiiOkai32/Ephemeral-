# Ephemeral

A native Kotlin / Jetpack Compose Android messenger with Nearby Connections and an optional internet relay. **Preview software, not a production-audited secure messenger.**

## Included

- Material 3 dark interface, conversation view, pairing confirmations and connection errors.
- Automatic P-256 daily device keys; both devices contribute to ECDH. HKDF-SHA256 derives AES-256-GCM keys with fresh connection challenges, random encryption nonces and authenticated date/message IDs. Connection challenges prevent captured ciphertext being replayed after a reconnect with the same daily keys.
- Android Keystore wraps the daily private key. Old keys are replaced on UTC rollover while running, or on next use after shutdown. Backup and screenshots are disabled.
- Nearby pairing requires matching the Google Nearby authentication digits on both phones. Internet invitations authenticate the daily public-key handshake using HMAC-SHA256; share invitations through a trusted channel. Compare the full daily safety number for additional verification.
- Text, built-in emoji stickers, and AAC voice notes (up to 60 seconds), all through the same encrypted channel. Voice playback is from memory. Temporary recording files are private and deleted after recording; app-start cleanup removes interrupted recordings.
- Foreground WebRTC audio/video calls, encrypted signaling, accept/decline, timeout, hangup, microphone mute and camera toggle. WebRTC encrypts call media using DTLS-SRTP.
- In-memory history, capped at 200 messages and 8 million text/base64 characters. History expires at midnight UTC and is lost when the process ends. There is no offline inbox or message recovery.
- A two-person WebSocket relay with room separation, input limits, heartbeat, backpressure, no message storage, and integration tests.

## Install the APK

A preview APK is provided under `downloads/` when generated. It is signed with a development key, **not a production distribution key**. Android 8.0+; Google Play Services is needed for nearby discovery. You must allow installation from your download app. Do not assume later builds will have a compatible signing key.

## Try nearby messaging

1. Open the app on two physical Android phones; enable Bluetooth, Wi-Fi, and Location.
2. Tap **Find nearby** on both phones and grant the requested permissions.
3. Tap the other phone, compare the pairing digits on both devices, and accept only if they match.
4. Open the connection, wait for the daily key exchange, then send text, a sticker, or a voice note.
5. Tap the lock to compare today's full safety number using a trusted channel.

Nearby messaging works without a server. Calls use WebRTC, which needs an IP path: put both phones on the same Wi-Fi, or give both internet access. Bluetooth-only Nearby connections do **not** provide a guaranteed WebRTC media path. Nearby transport chunks encrypted voice notes to fit the API's byte-payload limit.

## Internet setup (requires hosting)

**No public relay or TURN service is provisioned by this repository.** The APK intentionally has no invented/default server. Hosting must be configured before internet conversations can work.

1. Create a Node 22 web service from this repository using `render.yaml`, or deploy `relay/` to your preferred host. Build: `npm ci --omit=dev`; start: `npm start`; health: `GET /health`. The process listens on `PORT` (default 8080).
2. Terminate TLS at your hosting provider or reverse proxy and enable WebSocket upgrades. Use `wss://your-host` in the app. Never expose invitation codes in server logs.
3. Both people open **Internet invite**, enter the same relay URL, and privately share a generated invitation code. The app sends only SHA-256(invitation) as the room path. The invitation must be 43 URL-safe base64 characters, generated by the app.
4. Connect both phones. A room allows two simultaneous sockets; a third connection is rejected. A disconnect requires reconnecting manually; the app doesn't queue undelivered messages.
5. The **app owner** configures TURN once in the relay host's secret/environment settings:
   - `TURN_URLS`: the exact Metered `turn:`/`turns:` URLs, separated by commas.
   - `TURN_USERNAME`: the generated TURN username.
   - `TURN_PASSWORD`: the generated TURN credential/password, **not the account API key**.
   Restart/redeploy the relay after changes. Never commit these values or put them in APK build properties. Each paired client obtains ICE configuration over its secure WebSocket automatically; users do not enter calling credentials. Missing server configuration produces an app-owner configuration message when starting an internet call.
6. Once the relay's real hostname is available, build with `./gradlew assembleDebug -PEPHEMERAL_RELAY_URL=wss://your-host`. This non-secret URL is included in the APK, and the relay field is hidden. Without it, preview builds keep a relay field for the administrator. Ordinary users only exchange an invitation and tap Connect.

The relay sends TURN credentials to clients because WebRTC needs them; an installed client can inspect them. This implementation uses the credential configured on the server and does not mint per-user, short-lived credentials. Use limited/expiring credentials, rotate them at the provider and server, and add account-based authorization and provider-issued short-lived credentials before public-scale deployment. Pairing gates credential delivery, but anyone with two clients can create their own room; pairing is not a subscription or account authorization check. No Metered account API key is needed by this implementation or sent to clients. STUN alone cannot guarantee connectivity.

Provider example: https://render.com/deploy?repo=https://github.com/NiiOkai32/Ephemeral-

The relay is a minimal self-hosted service. Before a public rollout, add infrastructure-level connection/IP quotas, operational monitoring without sensitive payloads, and abuse controls. Leaked invitations allow impersonation; generate a new invitation for each conversation.

## Build and test

Use JDK 17+, Android SDK platform 35, and Build Tools 34.0.0. Set `ANDROID_HOME` or `sdk.dir` in untracked `local.properties`.

```sh
./gradlew testDebugUnitTest lintDebug assembleDebug --no-daemon
cd relay
npm ci
npm test
```

The Gradle 8.7 wrapper includes distribution SHA-256 verification. CI runs Android checks and relay integration tests and uploads the APK as a workflow artifact. No API keys, cloud accounts, or developer credentials are embedded in the APK. The unrelated starter Gemini feature was removed because it embedded a developer key at build time.

## Security and delivery limits

This is a custom protocol, not Signal's audited Double Ratchet. Keys rotate daily rather than per-message, and compromise of a daily private key may expose captured traffic for that day. There is no hardware-backed sender attestation, account directory, contact recovery, or cross-device sync. Pairing / invitation authentication and safety-number verification are essential. Media, contacts and chat text exist in process memory while used; Android screenshots are blocked but a compromised device remains outside this protection.

"Sent to transport" means queued to Nearby or WebSocket, **not a delivery/read receipt**. Voice notes and daily expiration require two-device testing. Calls only ring within the open app, end when the activity leaves the foreground, and do not have push notifications, background calling, Telecom integration, or lock-screen answering. Bluetooth-only video/audio is not supported without an IP route.

See [VALIDATION.md](VALIDATION.md) for checks run and remaining device tests. Publishing requires your own hosting and two-device validation before this can be described as a fully finished internet calling app.
